# Implementation results: fixed-topology geometry, the exec-keeping tier, and the baked-rig mode

Date: 2026-09-13. Plan: `reports/perf-implementation-plan.md`. Analysis: `reports/biped_eval_trace_analysis.md`.
Change-by-change log: `reports/rigexec-perf2-CHANGES.md` (the diff itself is this commit; the standalone patch files stay untracked next to it).

## 1. What landed

Everything in the plan except the NEON kernel (G5), which was dropped because a float NEON path would break
the byte-identity gate on this ARM host for a ~0.1 ms prize. Three tracks were implemented in separate copies of
the patched base, merged, reviewed by three adversarial agents (dynamic-path semantics and thread-safety; baked
fidelity and invalidation; test coverage by mutation), fixed up, and then given a second pass for the should-fix
items. That second pass landed all eight should-fix items: the baked program is now built lazily on the first baked frame after a scene edit (turning the mode on after an edit used to build nothing for the rest of the epoch), mover-graph counters and diagnostics are carried across an in-epoch rebuild and the parity comparator checks thirteen domains (solver-evaluation counts are deliberately excluded, because the dynamic path answers a repeated time code from its per-batch cache while the program re-solves), every shipped example stage is swept by a ctest in both modes, every ctest entry has a 120 s timeout, the static-input cache is cleared symmetrically on override set and clear, and an unrelated scene edit no longer re-runs the skin kernel once.

| track | items | new public surface |
|---|---|---|
| G, geometry | G1 per-epoch skin topology (`RigExecSkinTopology`, evaluator-owned cache, refused when the layout is time-varying, connected or chain-driven, re-decided after any notice); G2 constant full-strength envelope fast path; G3 `WorkParallelForN` inside the LBS kernel and the envelope blend (grain 512, threshold 4096) behind the one kill switch `RIGEXEC_ENABLE_PARALLEL_EVAL`, which also governs the two compile-time tasks; G4 level-parallel chain walk over contiguous dependency levels of `_chainOrder`, classified safe at Compile, per-chain work buffers merged in chain order | `RigExecSkinTopologyCache`, `RigExecParallelEvaluationEnabled()`, `GetChainLevelCount/Targets`, `IsChainLevelParallel`, `GetLiveGraphCount` |
| T, exec-keeping | T1 epoch-constant rest frames pulled once at Compile, refused for time-varying, connected or chain-written rest channels, re-classified after every notice, pulled per frame with the standing overrides while an interactive override touches a rest; T2 the missed `HasAuthoredConnections` guard and `RigExecStaticInputCache` (admitted only with no connections, no time variation and zero time samples; cleared on every notice and on override changes; bypassed off its owning thread); T3 the first frame's exec warm paid at Compile at the stage's start time code, never Default | `RigExecStaticInputCache`, `GetEpochRestFrameCount` |
| B, baked mode | B1 `RigExecBakedProgram`: dense slots, a binding table that reads per frame anything time-varying (including single-sampled), connected or chain-produced and captures the rest; op list of property chains, provider compose, solver kernels, constraints with precomputed propagation, matrices, skin (sharing G1's topology and G2's fast path through one shared kernel and one shared predicate), derived extent, publication; B2 `IsBakeable(&reasons)`; B3 a four-set capture index generated by the bake pass, notice-driven rebuild without recompile, overrides placed as forced resolved reads on every attribute of a connection walk; B4 `SetEvaluationMode(Dynamic|Baked|BakedWithParityCheck)` with the parity mode publishing the dynamic answer; B5 tests | `RigExecEvaluationMode`, `SetEvaluationMode`, `GetEvaluationMode`, `IsBakeable`, `RigExecComparePoses`, `RigExecRigPose::bakedParityMismatches`, `GetBakedProgramBuildCount`, `GetBakedGenerationCount`; python `evaluation_mode`, `is_bakeable()`, `bakeability_reasons()`; `rigExecPose --mode dynamic|baked|parity`; `RIGEXEC_EVALUATION_MODE` as a default selector for test runs |

Against the original trace: Compile 490 to 112 ms; static frame 30 to 7.1 ms dynamic and 0.6 ms baked;
animated frame 56 to 7.1 ms dynamic and 0.7 ms baked. The two compile ceilings are the only targets missed,
by 2-7% (the compile-time warm, which buys 8-9 ms off the first frame) and by 14-16% with the bake (built only
when the mode is requested; a lazy build on the first baked frame would move it off Compile).

Interactive and edit paths, biped, 40 generations each: a drag on a control avar 9.3 ms dynamic vs 1.4 ms baked
with one program build for the whole drag; an unrelated scene edit costs zero rebuilds; a moved rest (a captured
constant the epoch digest cannot see) rebuilds once and then evaluates at 1.0 ms.

## 3. Verification

- Dynamic output byte-identical to the patched base (`--joints --targets` stdout, `--joints-out`, empty stderr)
  on `Biped.usda`, `Biped_layered.usda`, `Biped_anim.usda`, the 5- and 9-mesh stages, and all 43 shipped example
  stages; identical with `RIGEXEC_ENABLE_PARALLEL_EVAL=0` and with `PXR_WORK_THREAD_LIMIT=1`; epoch digest unchanged.
- Baked output byte-identical to dynamic on the same stages. The example-sweep test opens 35 rig stages under
  `examples/`: 10 bake and 23 decline naming the blocking feature (the earlier manual sweep counted 22 of 45 files
  before single-sampled inputs and chain-written rests were made to refuse); parity mode reports zero mismatches;
  four existing suites re-run under the parity check. Landing on top of the other session's guides gate exposed one interaction (the baked program published solver guides the dynamic path no longer did, fourteen parity mismatches per frame on the biped); the baked publication now honours the same gate, with a test.
- ctest: 49 entries in the base, 63 after; the failure set stays `{testRigExecCurvenet, testUsdNoodles}`
  (both pre-existing on this box) over repeated runs.
- Reviews: the three reviewers found 2 blockers and 9 must-fix items, all reproduced and fixed, none backed out;
  12 regression mutants all killed by the suite afterwards. The blockers shared one root cause worth remembering:
  USD reports `ValueMightBeTimeVarying()` false for an attribute with exactly one time sample, while a read at
  `Default` never consults samples, so every admission and capture test now also requires zero time samples.
  The must-fix items were mostly decisions taken once at Compile that the epoch digest could not reopen (rest
  channels or skin layouts becoming time-varying after Compile) and missing tests for the safety guards.

## 4. Landing

Landed into the working tree on 2026-09-13 at 05:35, uncommitted, by a three-way merge (base: the
2026-09-12 21:30 snapshot; ours: the reviewed tree; theirs: the working tree as edited by the other session).
Twenty-seven files: sixteen modified, eleven new (`libs/rigExec/bakedProgram.{h,cpp}`, `parallel.{h,cpp}`,
seven test files, `examples/biped/Biped_anim.usda`). The other session's edits (pose-seed and guide snapshot
caches, `SetSolverGuidesEnabled`, a derived-result cache, two test additions) are all preserved. Six hunks
conflicted, all in `rigEvaluator.{cpp,h}`; four were additive and keep both sides, the pose-seed hunk places our
executor warm inside their cache-miss branch, and their derived-result cache was made safe for the parallel
chain walk: its entries are pre-created at Compile like the live graphs, reset rather than erased on a notice,
and its early exit publishes through the per-chain work buffer and still counts the revision.

Verified in the tree itself after landing: the build (every target except the pre-existing usdNoodles
`GL/glu.h` failure), the full suite with only `testRigExecCurvenet` failing (pre-existing), dynamic output
byte-identical to the patched base and baked output byte-identical to dynamic on the three biped stages, digest
16236336116187278719. Timing of the in-tree binary, min of 5: Compile 110 ms dynamic / 137 ms with the bake;
animated frame 6.3 ms dynamic and 0.65 ms baked (first frame 10.9 / 2.3 ms); static frame 3 5.8 ms dynamic.

To use the baked mode: `rigExecPose <stage> --mode baked` (or `--mode parity` to check it), `Rig.evaluation_mode
= "baked"` from python, or `SetEvaluationMode(RigExecEvaluationMode::Baked)` in C++; `is_bakeable()` and
`bakeability_reasons()` say why a rig declines. `RIGEXEC_ENABLE_PARALLEL_EVAL=0` is the one kill switch for
every rigExec parallel region, compile tasks included.

## 5. Follow-ups

- Build the baked program lazily on the first baked Evaluate to take the 25 ms bake off Compile.
- The dynamic path's compile ceiling: T1's separate rest request costs 1.7 ms of Prepare; the rest of the
  overshoot is the warm, which is worth keeping.
- A NEON LBS kernel in double precision if a bit-identical one can be written; ~0.1 ms per frame.
- The per-Compile prim index from the analysis (section 8) remains the next compile win (~85 ms of untraced
  schedule and request bookkeeping).
- Rest-channel interactive overrides now take the per-frame path for the whole drag; a rig that drags rests
  constantly pays the old rest cost while dragging.
